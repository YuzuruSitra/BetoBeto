# BetoBeto — おばけのスイーツキッチン

`Comcept/comcept.md` に沿った、Unity 6000.6.0f1 / URP のプレイ可能な初期プロトタイプです。
見た目とサウンドは差し替え前提の仮素材です。キャラクター・壁・床・罠・パイプ・アクション配置物は実際のPrefabになっています。

## 起動

1. Unity Hubからこのプロジェクトを開く。
2. `Assets/BetoBeto/Scenes/Title.unity` を開き、Play。
3. 「ステージを選ぶ」からキッチンを選択して開始。

主要ビルドターゲットは **WebGL** です。ゲームパッドを接続して使用します。

1. Unityメニューの `BetoBeto → Build → WebGL` で `Builds/WebGL` に出力。
2. プロジェクト直下で `python Tools/serve_webgl.py` を実行し、`http://localhost:8090` を開く。
3. 読み込み後「クリックしてはじめる」を押し、パッドのボタンを押して認識させる。

WebGLはHTTP配信が必要です。`index.html` のダブルクリック（`file://`）ではブラウザの制限により起動しないことがあります。ローカルでは上記サーバー、またはUnityの「Build And Run」を使います。サーバーは確認中起動したままにし、終了する場合はそのターミナルでCtrl+Cを押します。公開時は `Builds/WebGL` 全体を同じ構成で配信してください。Gzip圧縮とUnityの展開フォールバックを有効にしてあります。最初のクリックはブラウザの音声開始に必要です。旧Windowsビルドは今回の変更を含みません。

UnityのPlay開始シーンにもTitleを設定しています。別のシーンを編集していても、Playするとタイトルから始まります。
`BetoBeto → Create Initial Prototype` は不足している初期アセット／シーンの生成と、Build Settingsの登録に利用できます。既存Prefabと既存シーンの見た目は上書きしません。

## シーン構成

```text
Title.unity
    ↓
StageSelect.unity
    ├─ Kitchen.unity     16×9 / パイプ2 / 固定刃4＋横移動刃1
    └─ Kitchen02.unity   20×12 / パイプ3 / 固定刃6＋横・縦移動刃各1
                ↓
           Result.unity
           ├─ 同じステージに再挑戦
           └─ ステージ選択に戻る
```

タイトル・ステージセレクト・リザルトは、それぞれ本編とは別のシーンです。遷移はSingleモードで行い、本編のオブジェクトをアウトゲームに残しません。音量設定を持つ音声オブジェクトのみシーン間で維持します。ゲーム中のMENU / STARTは一時停止と音量設定を開きます。

## 操作とルール

| 入力 | 動作 |
| --- | --- |
| 左スティック / 十字キー | 移動。ゴーストはクッキーを通過可能 |
| 右スティック | その場で向きを変更。移動中も向きを指定可能 |
| 右側の4ボタンの下（Xbox A / PlayStation ×） | 足元のマスによだれ。メニューでは決定 |
| 右側の4ボタンの左（Xbox X / PlayStation □） | 驚かす。単押しは自分のマス＋前方1マス、長押しは周囲。離すと発動 |
| MENU / START | 一時停止／復帰、メニューの設定を開閉 |
| 右側の4ボタンの右（Xbox B / PlayStation ○） | 戻る／一時停止から復帰 |
| メニューで左スティック / 十字キー | 選択を移動。音量バーでは左右で音量調整 |

ボタンの名称が違うパッドでも物理的な位置で操作します。顔と足元の矢印が向きを表し、停止中も向きを保持します。スティックの小さな揺れを無視し、斜め付近では向きが頻繁に切り替わるのを抑えています。紫色の枠は自分のマスと前方1マスを囲み、単押しで驚かす対象を示します。よだれは常に足元です。

ゲームパッドが未接続なら開始カウントとフルーツの進行を待機します。プレイ中の切断は自動で一時停止し、再接続後に復帰操作を行います。キーボード／マウスによる本編の移動と設置は廃止しました。画面上のメニューボタンはマウスでも押せます。

驚かすボタンを0.25秒未満で離すと、自分のマスと向いている前方1マスの敵が、プレイヤーが向いている方向へ進みます。自分と重なっている敵にも効きます。0.25秒以上ためると自分を中心とする範囲効果に変わり、半径1〜6マスへ段階的に広がります。1.5秒で最大チャージとなり、離すまで保持できます。範囲は各フルーツがいるマスの中心で判定する円形で、壁越しにも届きます。チャージ中も移動・向き調整・よだれ設置が可能です。床の紫色の枠／円と白いゲージ、HUDに現在の範囲が表示されます。

驚かされたフルーツは、単押しならプレイヤーが向いている方向、長押しならプレイヤーの実際の立ち位置から離れる方向を向き、約1.5秒間逃走状態になります。逃走中も壁やシュレッダーに進路をふさがれたら、通常歩行と同じ右・左の交互転向を使います。安全な道がなければ待機します。途中で驚かされた場合も位置を飛ばさずに方向を変えます。滑走中に驚かすと滑走方向が変わり、連鎖数は維持されます。ポーズやパッド切断ではチャージが取り消されます。

例外として、驚かせた瞬間に逃げる方向の隣接1マスがシュレッダーなら、よだれなしでも回避せず飛び込み、収穫できます。単押し・長押しとも対象で、2マス以上先や横・後ろの刃には飛び込みません。メロンの耐久と無敵時間は維持されます。

よだれは初期設定で10秒で消え、再使用待ちは0.3秒です。驚かすには再使用待ちがなく、単押しの連続使用や発動直後の再チャージが可能です。壁・ゼリー・壊れていないクッキーやスコーン・パイプ・シュレッダーにはよだれを置けません。外周の床や壊れたお菓子のマスには置けます。氷の壁は、配置済みの水たまりを驚かすことで出現します。

歩行中のフルーツは壁や障害物まで直進し、当たるたびに進行方向を基準として右→左→右と交互に90度曲がります。全員が右折から始め、交差点だけでは曲がりません。曲がる側がふさがっていれば反対側へ進み、次は実際に曲がった側の反対を優先します。両側ともふさがった袋小路では後退し、進路がなければ待機します。左右の順番は各フルーツが保持し、驚かす・滑走・袋小路の後退では進めません。

イチゴは標準速度、ブルーベリーは高速、オレンジは低速です。オレンジだけは歩行中にもクッキーへ体当たりし、1接触につき1ダメージを与えます。壊せなければ短い反動の後に右・左の交互転向を行い、その衝突で壊せたら直進して通り抜けます。破壊時は次に曲がる左右の順番を維持します。メロンは最初のシュレッダー接触を耐えて跳ね返り、短い無敵時間の後にもう一度当てると収穫できます。

出口は配置不要です。外周を床で開け、フルーツが上下左右いずれかの盤面境界を越えると脱出になります。外周の床に乗っただけでは脱出しません。旧JSONの `E` は床として読み込み、既存シーンの出口表示もゲーム中は非表示にします。

フルーツパイプは供給専用で、歩行・滑走とも盤面からの逆走を防ぎます。出現したフルーツは下方向へ出て、出現直後に驚かされても管の奥へ戻りません。見た目は食品用の透明ガラス管に、銀色の留め具、白いパッキン、逆流防止フラップを組み合わせています。

フルーツは通常移動中、シュレッダーを障害物として避けます。安全な道がなければ止まり、自分から刃には入りません。**よだれで滑らせてシュレッダーに突っ込ませるのが基本の収穫方法**です。刃の隣で驚かせた場合は、前述の直接突入も使えます。

よだれに触れたフルーツは、そのときの進行方向へ滑り始め、ギミックで反転・転向しながら進みます。ほかのフルーツに触れると巻き込み、同じ連鎖の基準速度が上がります。チョコ付着中は各フルーツに減速倍率を掛けます。得点は1体につき100点×連鎖数。同じ刃での連続収穫は得点表示を合算します。壊れない壁への激突ではフルーツが潰れて跳ね返り、短く硬直します。壁への激突だけでは収穫されません。

硬直中のフルーツに後続が当たった場合は、衝突を予約して硬直終了後に滑走を再開します。硬直時間はリセットしません。接触が続いている同じ2体は重複処理せず、一度離れれば同じ連鎖でも再び巻き込めます。再参加では連鎖数を重複加算しません。別々の連鎖で滑走中のフルーツ同士が当たった場合は、連鎖を合流させます。メロンのシュレッダー無敵時間中も巻き込みは有効です。

滑走にはよだれの軌跡と飛沫、衝突には衝撃波・壁の揺れ・カメラの揺れ・短いヒットストップ・音程が上がる連鎖音を付けています。レシピの全種類が必要数そろうとクリア。違う種類の余剰分では代用できません。脱出上限に達すると失敗です。

## お菓子のギミック

よだれで滑り始めたフルーツを、反転・転向・破壊・減速でつないで刃へ送ります。6種類のギミックをステージエディタから配置できます。

| 配置物 | 動作 |
| --- | --- |
| ゼリー `J` | 180度跳ね返り、滑走・連鎖を維持 |
| クッキー `C` | 滑走衝突またはオレンジの体当たり3回で破壊。最後の一撃は通り抜け、20秒後に復帰 |
| 移動シュレッダー `H` / `V` | 横/縦に1マス/秒で往復。障害物で反転し、滑走中のフルーツを収穫 |
| スコーン `1`〜`4` | 斜面から乗ると歩行・滑走とも90度転向。斜めではない側面は壁扱い。滑走衝突20回目で壊して直進し、一時的に床扱い。5秒後に復帰 |
| チョコフォンデュ `F` | 歩行・滑走を3秒間0.35倍に減速。チョコのコーティングで状態を表示 |
| 氷ブロック `I` | 水たまりを驚かすと氷の壁に。通常5秒で溶ける。滑走1撃で破壊予約し、最後の衝突から0.5秒後に水へ戻る |

氷ブロックは驚かす範囲（単押しは自分＋前方1マス、チャージは最大半径6マス）で水たまりからそり立ちます。歩行するフルーツは壁として右・左と交互に曲がり、滑走中の衝突では停止します。衝突のたびに破壊待ち時間が0.5秒へ戻るため、連続衝突中は5秒の自然寿命を超えても敵をせき止め続けます。衝突が途切れると水に戻ります。水にはよだれを置けますが、壁になった際に消えます。ステージエディタの「氷ブロック」で配置し、JSONをUnityへ読み込んでください。

四角いビスケット壁 `#` は壊れません。クッキーは破壊後20秒、スコーンは5秒で復帰します。どちらも復帰先にフルーツや移動刃がいる間は待機し、戻ると耐久を全回復して、そのマスのよだれを消します。復帰時間はステージごとに調整できます。チョコフォンデュは踏み直すと時間を更新し、減速は重複しません。すべてのギミックの時間は一時停止とヒットストップに連動します。

ゼリーと壊れていないクッキーは通常歩行では避けますが、オレンジは歩行中にもクッキーを削れます。スコーンには全フルーツが斜面側から歩いて乗れ、マスの中心に到達してから90度転向します。この転向では壁で曲がる左右の順番を進めません。斜めではない2つの側面は通常の壁と同じ扱いで、歩行では右・左の交互転向、滑走では衝突して停止します。歩行では耐久を削らず、滑走衝突は斜面・側面とも耐久を1回分削ります。滑走中の反射・破壊は全フルーツ共通です。移動刃は歩行中のフルーツを避けて反転し、通常の歩行では収穫されません。移動経路の途中で滑るフルーツと接触した場合も判定し、メロンは従来どおり2回の有効な衝突が必要です。ギミックによる反射・破壊通過・減速では連鎖数をリセットせず、ほかのフルーツを巻き込んだときに連鎖を増やします。

1番目のステージは、中央のゼリーと周囲のスコーンで方向を変え、クッキーに囲まれた固定刃や下段の横移動する刃へ送る配置です。2番目のステージには、右上のスコーンで下へ、右下のスコーンで左へ曲げて、クッキーの先の刃へ送る経路があります。チョコフォンデュと動く刃を組み合わせ、チョコ付着による到着時間の変化も利用できます。

数値はステージエディタの「ギミック」で調整できます。実装は `Stage/GimmickRules.cs`（反射・耐久・往復移動）、`Stage/GimmickController.cs`（ゲーム進行との連動・破壊表示・移動接触）、`Enemies/FruitAgent.cs`（滑走・チョコ付着・連鎖）です。6種類の見た目は `Prefabs/Stage` のPrefabとして差し替えられます。氷の破壊待ち時間は0.5秒固定です。

## 独立ステージエディタ

`Tools/StageEditor/index.html` をChromeまたはEdgeで直接開いて使用できます。Unity、サーバー、npmのインストールは不要です。インターネットにも接続しません。

- 左ドラッグ：選択した配置物でペイント。右ドラッグ：床に戻す。
- ホイール：カーソル位置を中心に拡大縮小。
- 中ボタンドラッグ／Space＋左ドラッグ：パン。
- 1〜5：ブラシ選択（壁・床・パイプ・シュレッダー・開始位置）。F：全体表示。
- 6種類のギミックを追加配置可能。移動刃は横・縦のブラシを選び、スコーンはRまたは回転ボタンで90度ずつ回転。氷ブロックは水たまりとして配置。
- Ctrl+Z：Undo。Ctrl+Shift+Z / Ctrl+Y：Redo。
- ステージ名、サイズ、必要フルーツ数、脱出上限、出現間隔、よだれと氷の壁の寿命、クッキーの耐久、クッキー・スコーンそれぞれの復帰時間、刃の速度、チョコ付着時間・速度倍率を編集可能。
- 端末内への自動保存、JSONの読み込み／書き出し、配置数と到達可能性の検証。

### Unityへの取り込み

「JSONを書き出す」はファイルの保存です。Unityに反映するには、保存したJSONをインポーターで読み込みます。

#### 新規ステージを追加する

1. エディタで検証エラーを解消して「JSONを書き出す」。
2. Unityの `BetoBeto → Stage JSON Importer` を開く。
3. JSONを指定して「検証」。
4. 「新しいシーンを生成して保存」を選び、未使用のシーン名で保存する。
5. カタログとBuild Settingsに自動登録され、ステージセレクトから選択可能になる。

#### 既存ステージを更新する

1. Unityの再生を停止し、`BetoBeto → Stage JSON Importer` を開く。
2. 「JSONを選択」で書き出したファイルを指定し、「検証」を押す。
3. 「更新するシーン」に既存シーンを指定する。Projectからドラッグするか、右端の選択ボタンで選べる。開いているゲーム本編のシーンは「開いているステージを選択」でも指定できる。
4. 「既存シーンを更新して保存」を押す。
5. 再生し、ステージセレクトからそのステージを選ぶ。WebGL版で確認する場合は、`BetoBeto → Build → WebGL` で再ビルドする。

同梱の1番目「はじめてのキッチン」は `Assets/BetoBeto/Scenes/Kitchen.unity`、2番目は `Assets/BetoBeto/Scenes/Kitchen02.unity` を指定します。

更新では、`Stage / Tiles` と `Stage / Placements` 内をJSONから再生成します。この範囲でUnity上だけで行った個別の配置・見た目の調整も置き換わります。シーンのGUID、StageLayoutとGameControllerの参照、カメラ・照明・それ以外の配置は維持し、生成されたキッチン天板の幅・奥行きは盤面サイズに合わせます。

ステージ名、レシピ、ギミックなどのルールと、ステージセレクトのプレビューも更新します。登録済みステージのID・並び順・説明を保ち、同じステージを重複追加しません。参照元JSONは同じファイルを更新し、複数ステージで共有している場合は更新対象用のJSONを作ります。タイトルなどゲーム本編以外のシーンや、不正なJSONは反映前にエラーになります。

生成される `Stage / Tiles` と `Stage / Placements` の中身はPrefabインスタンスです。見た目の調整は各Prefab、位置調整はシーン上のインスタンスで行えます。実行時はシーンに存在する配置物から当たり判定を作り直すため、Unity上で移動した壁や罠も反映されます。配置は1マス単位で行ってください。エディタのプレビューは元JSONを表示するため、Unityだけで配置を変更した場合のプレビューは更新されません。

ステージの一覧・表示名・説明は `Assets/BetoBeto/Resources/StageCatalog.asset` で編集できます。

## 開発の分担

| フォルダ | 担当する内容 |
| --- | --- |
| `Assets/BetoBeto/Core` | ゲーム進行、勝敗、得点、シーン遷移、ステージカタログ |
| `Assets/BetoBeto/Player` | ゴーストの移動と入力 |
| `Assets/BetoBeto/Enemies` | フルーツAI、滑走、連鎖、メロン耐久 |
| `Assets/BetoBeto/Stage` | JSON仕様、グリッド座標、配置物と盤面 |
| `Assets/BetoBeto/UI` | 共通UI、ゲームHUD、各アウトゲーム画面 |
| `Assets/BetoBeto/Audio` | 独立したBGM／効果音音量、仮サウンド |
| `Assets/BetoBeto/Presentation` | 滑走の軌跡・飛沫・連鎖表示・壁の反動・ヒットストップ・収穫エフェクト |
| `Assets/BetoBeto/Prefabs` / `Art` | 差し替え可能なモデル、マテリアル、メッシュ |
| `Assets/BetoBeto/Editor` | Prefab生成、JSONからシーン生成 |
| `Assets/BetoBeto/Stages` / `Scenes` | ステージデータと各シーン |
| `Assets/BetoBeto/Tests` | EditMode／PlayModeテスト |
| `Tools/StageEditor` | Unityに依存しない配置ツール |

ゲーム画面のUIはラフ画像に準拠せず、レシピ進捗・脱出数・操作が読み取れる独自構成です。仮BGM・効果音はコードで合成し、音量はPlayerPrefsに別々に保存します。日本語フォントはM PLUS Rounded 1cを同梱しています。ライセンスと出典は `Docs/third-party.md` に記載しています。

滑走速度と壁での硬直は `Enemies/FruitAgent.cs`、揺れ・飛沫・ヒットストップの強さは `Presentation/GameFeedback.cs`、残像と潰れ方は `Presentation/FruitMotionVfx.cs` で調整できます。滑走は初速7.5マス/秒、巻き込み1体ごとに0.65マス/秒加算（加速は6体分まで）、壁の硬直は0.48秒です。

フルーツ4種類は `Assets/BetoBeto/Art/Characters/Fruits` のリグ付きモデルを使用します。驚かされた後は3秒間、驚き顔で両手を上げてバタバタ走ります。滑走中も驚き顔になり、滑走開始ごとに仰向け・うつ伏せのモーションをランダムに選びます。導入元・サイズ・表情切り替え・検証記録は `Docs/fruit-models.md` を参照してください。

お化けは `Assets/BetoBeto/Art/Characters/CuteGhost` のリグ付きモデルを使用します。移動速度でIdle／Moveをブレンドし、よだれボタン押下中はカメラを向いてYODAREStart→Yodareを連続再生し、Yodareボーンから透明なよだれが床に落下します。離すと通常動作へ戻り、怖がらせるときはSpookを0.5秒再生します。Blend更新後は `Tools/Blender/Export-CuteGhost.ps1` で再出力できます。設定と再出力手順は `Docs/ghost-models.md` を参照してください。

驚かす範囲・チャージ時間・逃走時間は `Player/ScareRules.cs`、チャージと範囲の表示は `Presentation/ScarePreview.cs`、よだれの再使用待ちは `Core/GameController.cs` の `DroolReuseSeconds` で調整できます。旧能力の氷Prefabは互換性のため残しています。水たまりから生じる氷の壁は `Prefabs/Stage/IceWall.prefab` を使い、JSONの `iceLifetime` で寿命を調整します。

## 検証コマンド

同梱のUnity Pipelineとインストール済みUnityCLIを使用できます。

```powershell
$unityCli = "$env:LOCALAPPDATA/Unity/bin/unity.exe"
& $unityCli command --project-path . recompile
& $unityCli command --project-path . run_tests --mode editor --filter BetoBeto.Tests.EditMode --filter_type assembly
& $unityCli command --project-path . eval --code 'UnityEditor.SceneManagement.EditorSceneManager.playModeStartScene = null;'
& $unityCli command --project-path . run_tests --mode playmode --filter BetoBeto.Tests.PlayMode --filter_type assembly --async_tests true
& $unityCli command --project-path . test_status
node Tools/StageEditor/stage-model.test.cjs
```

JSONの詳細は `Docs/stage-format.md` を参照してください。
実行したテストと画面確認の範囲は `Docs/verification.md` にまとめています。

PlayModeテスト中はタイトル固定を一時解除します。テスト完了後、`BetoBeto → Create Initial Prototype` で通常の起動設定に戻せます。Unity 6000.6 / Pipelineの組み合わせで `test_status` がrunningのままになる場合、Unityが出力する `AppData/LocalLow/BetoBeto Kitchen/BetoBeto/TestResults.xml` にテスト結果が保存されます。
